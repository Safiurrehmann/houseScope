# A short technical demonstration

1. **Document map:** open the Kentucky sample, select page 16 and toggle text-block outlines. Explain that page identity and word geometry are retained before the model sees anything.
2. **Pipeline trace:** show the staged run, section cache count, token usage and cost. Explain that only observation extraction uses Luna; review and planning never call the model.
3. **Findings:** open an electrical observation. Show exact highlighted evidence, the locally bound inspection reference, and the priority rule. If summary and detail were consolidated, switch sources and inspect original variants.
4. **Review:** correct a title or interpretation and save with a note. Show the new revision and history. Reject an irrelevant finding and show that it leaves the repair plan. Do not change original source evidence.
5. **Repair graph:** show one shared electrician evaluation for multiple findings, rather than a separate diagnostic charge per defect. Show moisture investigation before source correction and explain that related drainage is only a hypothesis.
6. **Evaluation:** show the original extraction's one-to-one reference matches, misses and unmatched predictions. Point out the excluded untested dryer and the distinction between source localization and semantic correctness. Do not hide bad results or claim independent human annotation.
7. **Export:** download evidence JSON and review annotations to demonstrate that provenance, errors and corrections are machine-readable.

The engineering claim is about traceability, explicit decision policies, controlled costs, recoverable processing and measurable failures. Any accuracy or latency numbers must come from a recorded run, not this script.
